# Аналітичний звіт: Вибір стека для стартапу-маркетплейсу послуг

## 1. Вступ та контекст
Стартап розробляє маркетплейс послуг з обмеженим бюджетом та жорстким дедлайном до MVP у **4 місяці**. Команда складається з **2 розробників із досвідом веб-фронтенду** (HTML, CSS, JavaScript, React). 

Мета цього звіту — порівняти кросплатформні фреймворки (Flutter, React Native) із нативною розробкою (Swift/Kotlin), оцінити ризики для платформ Android та iOS, побудувати дерево рішень та надати остаточну рекомендацію.

## 3. Оцінка ризиків для Android та iOS

### 3.1. React Native
* **Android:** Ризики пов'язані з фрагментацією Android-пристроїв та дещо нижчою продуктивністю на бюджетних смартфонах під час складних анімацій, проте нова архітектура (Fabric/JSI) мінімізує цю проблему.
* **iOS:** Здебільшого ризики мінімальні, оскільки RN використовує нативні UI-компоненти iOS, що забезпечує звичний для користувачів Apple інтерфейс.

### 3.2. Flutter
* **Android:** Завдяки власному рушію рендерингу (Skia/Impeller) гарантується 100% ідентичність UI на всіх пристроях. Ризики мінімальні.
* **iOS:** Існує ризик відторгнення користувачами через "не зовсім нативний" вигляд стандартних жестів та навігації iOS, оскільки Flutter малює власні віджети, а не використовує системні.

### 3.3. Нативна розробка (Swift / Kotlin)
* **Android:** Вимагає знання Jetpack Compose. Головний ризик — повне невиконання дедлайну через брак експертизи у поточної команди.
* **iOS:** Вимагає знання Swift, конфігурації сертифікатів Apple. Ризик значного перевищення бюджету через необхідність аутсорсу.
