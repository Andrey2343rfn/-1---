# -1---# Аналітичний звіт: Вибір стека для стартапу-маркетплейсу послуг

## 1. Вступ та контекст
Стартап розробляє маркетплейс послуг з обмеженим бюджетом та жорстким дедлайном до MVP у **4 місяці**. Команда складається з **2 розробників із досвідом веб-фронтенду** (HTML, CSS, JavaScript, React). 

Мета цього звіту — порівняти кросплатформні фреймворки (Flutter, React Native) із нативною розробкою (Swift/Kotlin), оцінити ризики для платформ Android та iOS, побудувати дерево рішень та надати остаточну рекомендацію.

## 3. Оцінка ризиків для Android та iOS

### 3.1. React Native
* **Android:** Ризики пов'язані з фрагментацією пристроїв та роботою важких сторонніх бібліотек, проте нова архітектура (New Architecture з JSI) значно підвищила стабільність та продуктивність у 2026 році.
* **iOS:** Ризики здебільшого мінімальні. Добре інтегрується з нативними компонентами через компонентну модель, легке підключення Apple Pay.

### 3.2. Flutter
* **Android:** Рендеринг за допомогою рушія Skia/Impeller гарантує ідеальну ідентичність UI, проте можливі труднощі з інтеграцією специфічних нативних платіжних віджетів чи системних жестів.
* **iOS:** Використання рушія Impeller забезпечує стабільні 120 FPS, однак нативний дизайн та стандартні навігаційні патерни потребують додаткових зусиль для адаптації порівняно з React Native.

### 3.3. Нативна розробка (Swift / Kotlin)
* **Android:** Потребує глибоких знань Kotlin, Jetpack Compose та специфікацій безпеки Android. Ризик невиконання дедлайну через брак навичок у команди.
* **iOS:** Вимагає знання Swift, SwiftUI та налаштування сертифікатів розробника Apple. Критичний ризик перевищення бюджету та зриву запуску MVP.
